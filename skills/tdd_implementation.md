# TDD-реализация

Пиши код по принципу «тест сначала». Никогда не возвращай пустой `changes` без `escalation`.

## Процедура

1. Для каждого критерия приёмки напиши тест, который упадёт на пустой реализации.
2. Реализуй минимальный код, проходящий все тесты.
3. Не добавляй функциональность, которой нет в критериях.

## Признаки провала

- `changes: []` при непустом плане и пустом `escalation` — тихий провал. Если план противоречив — эскалируй. Если не можешь сгенерировать код — эскалируй. Не возвращай пустоту.
- Тест с `assert True` — не покрывает ничего. Перепиши на проверку ожидаемого значения.
- `notes: "Реализовано"` при пустом `changes` — ложь. Поле `notes` должно отражать реальность.

## Пример

Критерий: `multiply(3, 4) == 12`

Плохой тест (бесполезный):
```python
def test_multiply():
    assert True
```

Хороший тест:

```python
def test_multiply_positive():
    assert multiply(3, 4) == 12
```
